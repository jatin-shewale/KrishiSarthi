1. Project Overview

1.1 Purpose

The project involves developing KrishiSarthi, a smart agricultural equipment rental
platform designed to help farmers access farming machinery such as tractors,
harvesters, tillers, sprayers, rotavators, cultivators, and other equipment on demand.
Unlike traditional offline rental arrangements, this system provides a digital platform
where farmers can register, list their own machinery, browse available equipment,
request bookings, complete payments securely, and receive agricultural support through
weather insights and an AI-powered farming assistant.

1.2 Target Users

Farmers: For browsing, renting, and listing agricultural equipment
Equipment Owners: For publishing equipment details and managing rental requests
Administrators: For approving equipment listings, monitoring bookings, and tracking
platform statistics

1.3 Core Features

User Authentication: Secure registration and login with JWT-based access control
Equipment Management: CRUD operations for machinery listings with image upload
Marketplace Search: Search and filter by equipment category, location, owner, and price
Booking System: Rental request creation, approval workflow, and booking status tracking
Payment Integration: Stripe checkout flow for secure online booking payments
Admin Dashboard: Moderation of users, equipment, and bookings with platform analytics
Weather Module: Localized weather insights with farming suggestions using OpenWeather
AI Assistant: Agricultural guidance for crops, fertilizers, pests, and soil management
Ratings and Reviews: Equipment rating system with average score calculation

2.2 Non-Functional Requirements

Scalability: System should support increasing numbers of users, equipment records, and bookings
Latency: API responses for marketplace, booking, and dashboard features should remain responsive
Availability: Frontend, admin portal, and backend should remain accessible during academic demo use
Security: Password hashing, JWT authentication, CORS protection, and role-based authorization
Usability: Mobile-responsive interfaces for farmers and administrators
Maintainability: Modular separation of frontend, backend, admin, routes, controllers, and models

3.1 Architecture Workflow

Authentication: User registers/logs in -> JWT token generated -> protected pages unlocked
Equipment Listing: Farmer uploads equipment details and image -> backend stores file path -> MongoDB saves record
Marketplace Search: User browses and filters equipment -> matching records returned from database
Booking Flow: Farmer submits rental request -> owner/admin reviews request -> status updated
Payment Flow: Approved booking -> Stripe checkout session created -> payment verified -> booking marked paid
Admin Monitoring: Admin logs in -> views users, equipment, bookings, and revenue metrics
Weather Assistance: Frontend sends coordinates -> weather API returns conditions -> suggestions displayed
AI Guidance: User sends farming query -> OpenAI-powered assistant returns agriculture advice
Ratings: Users submit reviews -> average rating updated for equipment

4. Development Methodology: Incremental Model

Recommendation: Incremental Model

The Incremental Model is suitable for KrishiSarthi because the project contains multiple
independent modules that can be built and validated in stages. Core marketplace and
authentication features can be completed first, followed by bookings, payments, weather,
AI support, and admin controls. This approach reduces integration risk and supports
continuous improvement during development.

Phases:

Phase 1: User authentication, farmer profile setup, and protected navigation
Phase 2: Equipment listing, marketplace browsing, and search/filter features
Phase 3: Booking requests, owner/admin approval workflow, and dashboard views
Phase 4: Stripe payment integration and transaction recording
Phase 5: Weather assistance, AI farming assistant, ratings, and deployment configuration

6. Metrics & Risk Management

6.1 Project Metrics

Code Quality: Modular organization with separate frontend, admin, backend, routes, controllers, and models
Performance: Responsive filtering, booking retrieval, and dashboard statistics for small to medium datasets
Security: JWT authorization, bcrypt hashing, protected admin routes, and CORS-based origin control
Reliability: Fallback behavior in weather service and structured booking/payment validation

6.2 Risk Mitigation

Risk                         Severity   Mitigation Strategy

Stripe Payment Failure       High       Verify payment status before marking booking as paid
Weather API Unavailability   Medium     Return fallback weather data and basic farming suggestions
OpenAI API Failure           Medium     Display graceful error handling for AI assistant requests
Unauthorized Access          High       Use JWT middleware, admin checks, and password hashing
Booking Status Errors        Medium     Restrict status updates to owners/admins and validate flow
SLOC Growth                  Medium     Maintain modular code structure and incremental delivery
Image Upload Issues          Low        Use Multer middleware and default image fallback

7. Conclusion

The COCOMO analysis indicates that KrishiSarthi fits the Organic project category for a
student-developed full stack platform. Based on approximately 5.2 KLOC of source code,
the estimated effort is 14.9 person-months, with an expected schedule of about 7 months
and a team size of around 2-3 developers. With an incremental development approach,
KrishiSarthi can be implemented and demonstrated effectively while integrating booking,
payments, weather intelligence, and AI-assisted agricultural support in a practical and
manageable way.
